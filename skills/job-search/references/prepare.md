# Prepare

Every job the skill plans to apply to (an `exact` or `confirmed` employer posting, above the score floor if set, within this period's most) is prepared with no question and no shortlist step, in every apply mode. Code runs the steps it can, in the watcher and in `J work`: a Greenhouse job's questions come from the public board API, the sheet is built, and a sheet with no new writing is checked and goes straight to `apply_ready`, with no model. `J work` lists `prepare_due` only when a sheet needs new writing, or when the questions need the browser first (every system but Greenhouse). The steps below are what the model does then:

1. Get the questions. Greenhouse: save the job's `questions=true` response from the public board API to a file and use it. Lever, Ashby and every other employer system give no form fields: pass 1 of the browser step reads the live form first (references/apply.md), then continue here with the fields it returns as `[{"label","required","type","maxLength","options"}]`. `options` holds the real option labels of one control, word for word, never a summary of a list. A field made of several controls (a month and a year dropdown, or a day, a month and a year) is one field with `"type":"date"` and `"parts":[{"name":"Month","options":[...]},{"name":"Year","options":[...]}]`, each part with its real labels. `J sheet build` and `J sheet check --live` refuse a summary (a ".." range between two values) and name the field: read it again with parts.
2. Each sheet field is tagged `fact`, `upload`, `answer` or `new_writing`; `sheet check` fails when a required field has no tag.
3. `J sheet build <key> --questions <file>`. It fills each field from the profile, saved answers, or a checked draft; it lists unanswered required fields and stops on forbidden labels.
4. Prose: one writer call per round covers every sheet that needs writing, plus the round's lead intros and contact intros. `J write-prompt --round` prints `{model, description, prompt}`; make one Agent call with exactly that `model` and `prompt`, save its reply and run `J write-result --round --result <file>`. Code checks each draft, rebuilds and checks the sheet, and moves a passing job on. (`J write-prompt <key> --questions <file>` and `J write-result <key> ...` remain for one job.) A failed or empty answer holds the job as stopped and goes in the report. Prepare runs before the browser, so a long writing job never holds a form open.
5. Unknown required fields: ask the person once and store with `J answer add --label L --value V --key <job>` (kept in `answers.json` with how it was given, the date and the source application). Code reuses an earlier answer only when the normalized question is equal, the field type matches, a select answer is still one of the options and the text fits the limit; anything else is new writing. A near match goes to the person.
6. Rebuild the sheet, then `J sheet check <key>`. If it passes, the job becomes `apply_ready`. If not, it is parked with a reason and waits for the person.
