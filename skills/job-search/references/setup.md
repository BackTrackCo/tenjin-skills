# Setup and the start

Setup asks only what it needs now; the rest comes when it matters. Nothing here asks about Tenjin or stops for it: `J tenjin` only sets the hint state (`missing`, `outdated`, `unfunded`, `ready`), and Tenjin comes up as a recommendation at a hint moment, after a free result (references/questions.md).

## The first run, in order

1. **The resume**, a plain question: the `next` text of `J start status`, said as given. Never ask for "the path", and never search the person's files. `J resume set --file <path>` (a path, or a file dragged into Claude Code, which arrives as a path; a PDF or Word file is read by you with your file reader, then `J resume set --text` saves its text), `J resume set --url <link>` (code fetches a public link once: that exact URL, https only, at most 3 redirects, local, private and never-automated hosts refused at each hop; a PDF is saved as `resume.pdf`, a page as `resume.txt`; a sign-in answer is reported, and a connector the person has connected may read it, otherwise ask for a public link, the file or the text) or `J resume set --text` (the text on standard input). A LinkedIn profile link is never fetched or opened by the skill: with Tenjin code reads it through the router (`linkedin_profile`); without Tenjin it is a hint moment and you ask for a PDF export (LinkedIn: More, Save to PDF) or the text. The link is read once; a new `J resume set` replaces it. When the read carries job titles and dates the profile is not thin: `J resume set` returns a `roleHint` (the current position first, then the titles), the role and role words come from it with `search.sources` saying `linkedin`, and the role is still confirmed with a choice question; the person's own titles and dates are kept for the warm-path check. A read with employers only stays thin. A file is also copied to the uploads folder (`~/.tenjin-skills/job-search/uploads/`, 0700), which holds only what a form takes, and a PDF from a link is saved there; `resume.txt` and the state files stay in the parent. Just before each upload, code copies that file into the working folder (`CLAUDE_PROJECT_DIR`, else the current folder) as `.job-search-upload/<its own name>` (`J uploads stage <key>`) and deletes the copy and the folder right after (`J uploads unstage <key>`); no folder grant and no question. An unwritable working folder fills the job without the file and says so in one report line. A text-only resume has no file: a form that needs one holds that job (`needs_resume_file`) and asks once for the file.
2. **Read the rest from the resume**, never as an open question: the role, the role words for the search rounds (synonyms and levels), the place (as the resume gives it, so a city stays that city) and remote (only if the resume or the person says remote). Save with `J profile set` and `search.sources` saying `resume` for each. Where the resume really leaves one open (two tracks, no recent role), ask one choice question: `J ask resume --json '{"header","question","guess","next"}'`, the guess first as "(from your resume)".
3. **One question-tool call** (mark "Four quick choices" done after `J start record`): `J ask start` prints it. Four questions: the apply mode ("Ask me each time (Recommended)", "Auto apply", "Fill only, I submit", "Just open the pages"; attended is the default and the answer when none is given; "Auto apply" asks `J ask auto` next, between "Auto apply, approve new answers", which still drafts the answer to a new required question while only that job's submit waits, and "Fully auto apply"), the search frequency (every day, twice a day, once a week) the positions ("50 now, 10 daily (Recommended)", "100 now, 20 daily", "20 now, 5 daily", "No limit", or "Other": your own numbers; "No limit" and no answer record nothing, never the recommended numbers: `J start record --no-limit`) and where to apply ("Employer's site (Recommended)", "A job site, I apply" (LinkedIn, Indeed, YC or another job site: I open the job's page in your browser and give you the answers, and do nothing on the site), "Ask me each job": `--where employer|site|ask`, stored as `apply.where` with source `person`; no answer means the employer's site; references/apply.md). Then say the reminder line `J start record` prints, if it prints one (code builds it from `J rc set on|unknown`, whether a push was ever sent, and the two push settings it reads, read-only, from Claude Code's own config: it names only the settings that are off or unknown and shows nothing when all is on; it is never a question and comes at most once per start). With Claude in Chrome off, options that need it carry a note (`J chrome set off`). Record the answers: `J start record --mode attended|auto_no_new|auto_write --frequency daily|twice_daily|weekly --catch-up <n> --per-day <n>|none --words "<their words>"` (older form: `--positions <n>|none|skip`). The catch-up applies once, to the first period; after it the daily number applies, split across a twice-a-day period (the first takes the odd one) and counted for 7 days in a weekly one. It is a most, not a target: no weaker fit fills it. Change them later, outside a batch, with the same command or `J frequency set`.
4. **An auto mode also needs**, shown back for a clear yes: the unattended rules (`profile.unattended`: `roles`, `places`, `remote`, `minPay`, `excludeCompanies`, `excludeLevels`, `minScore`, `hosts`: the hiring systems or `*` for any), then `J consent record unattended --optional-writing skip|wait` (the person picks; `J ask optional-writing`). For "Fully auto apply", `J consent record writing` too. The dry run comes before the first unattended submit.
5. **Then the free search and the report** in the same session (`J work`, references/search.md). The first report says what was searched, from where.

## Later, at their trigger

- Leaving other items: `J leave search web need:<kind> --reason no_web_search` (comes back at the next period) and `J leave contacts:<jobkey> --reason none_found`; a post batch is never left. `J retry <key>` is the person's own "try again"; `J fact set account <host>` says they have an account there (a `sign_in` job returns).

- A form fact (phone, work authorization, sponsorship, pay): the job holds as `needs_facts`; ask then with `J ask facts` (merged across jobs, references/questions.md) and record with `J facts answer <id> <value>`; `J fact set <name> <value>` saves a fact of your own accord.
- The voluntary demographic fields (gender, race or ethnicity, veteran status, disability), at the first form that has them: one plain question, never a choice (`J eeo question --key <job>` builds its text and names the form's fields), answered in the person's own words or "decline" and saved as text (`J eeo set`). On every later form match that text to the form's own options and record each match with `J eeo answer <key> <field label> <option>`; a field the text does not answer is never guessed: ask it plainly, for that field only, and add the answer with `J eeo add`. An optional field is asked too, marked optional, and the person can skip it: `J eeo skip <key> <field label>` leaves it empty and is saved, so no later form asks about it again; a required field cannot be skipped. A required field is asked in the session before the fill. An auto mode needs no EEO text at setup: in a turn the watcher wakes, the first form with fields the text does not answer holds its job as `eeo_missing` with one notification, and the next attended turn asks the plain question.
- A watched company: there is no question, and the skill never suggests one. A board joins the list only when the person asks in their own message, by naming a company or pasting a careers link: `J watch add <company or careers link>` (it goes in `profile.watch`). A company name uses the employer resolution; when it finds no board the command returns one plain line to say, which is not a question. The board stays until the person removes it (`J watch remove <name>`); nothing drops by itself.

## Profile shapes

`J profile set '<json>'` checks the shape and refuses a bad one with the reason: `places` list of strings, `remote`, `includeOld`, `updates`, `hn` and `yc` true or false, `frequency` daily, twice_daily or weekly, `windowDays` positive number, `sweepHour` 0 to 23, `watch` list of `{"url"}` (a board joins it only from the person's own request: `J watch add`), `apply` `{"where": "employer"|"site"|"ask", "source": "person"}`, `search` `{"role","place","remote","roleWords","variants","sources"}` (lists of strings; `sources` says `resume`, `linkedin` or `person` for each value), `facts` object of text, number or true/false, `eeoText` the person's own words for the voluntary demographic questions (an older `eeo` value is not converted: every command except `J profile` refuses it, with the field named, until `J profile set '{"eeo": null}'` removes it), `unattended` (lists of strings; `minPay`, `minScore` numbers). `search.role` also filters watched-board titles by its words; `search.roleWords` widens it.

## Other setup notes

- The watcher is `J watch`, a background command (Bash `run_in_background`) that ticks every minute, prints nothing on a quiet state and exits 0 with one line when work is due; that exit wakes the session, and the round ends by starting it again (it does not exit again for the same due set). It records its process id in the lease and refreshes a liveness field from a timer that runs through long ticks; a lease whose process is dead or whose field is older than twice the tick interval is reclaimed by the next `J arm`, and every J command reports `watcher: stopped` until it is started again. `J watch` refuses while due work the model can act on is unclaimed (`J work --commit` claims what it prints), so start it last in a turn. The Monitor tool is not used.
- Unattended turns that the watcher wakes can stop at a permission prompt, because the skill's `allowed-tools` grant clears at the next message; this skill writes no allow rules into settings. Open each allowed host's public board page once with the person present so Chrome allows the site for the session. Chrome stays open, the computer awake, the session open.
- The skill never installs Tenjin unasked, and changes no Tenjin setting.
- After `claude --chrome --resume` nothing runs by itself: the person sends any message, and then the every-start steps run in order (`J tenjin`, `J start status`, `J chrome set on|off`, `J rc set on|unknown`, `J arm`, `J work --commit`, `J watch` last).
- A push that comes back not sent: `J notify result not_sent --reason off|present|none`. `off` (the setting is off): say the `/config` sentence once; `none` (no transport): both sentences once; `present` (the person is at the terminal): nothing.
- An update waits for the person's yes (`update_waiting`, in the report and the notification): on a yes, `J release apply`; `J release check` checks now. Updates never change the person's rules, profile or writing rules.
- After a round with stops, `J lessons derive` records the tighten-only lessons the stops justify, `J lessons` lists them and `J rules remove <id>` removes one.
