# Setup

Run once, attended. Ask only what is missing; `J setup check` shows what is done. Save the stage as you go: `J setup stage <stage> <next step>`.

1. **Tenjin.** `J tenjin`. If missing or outdated, say once what Tenjin does here and ask whether to set it up. On a yes, follow the "Install Tenjin from tenjin.sh" flow (tenjin.sh/skills.md) and go on when it says ready; copy none of it and change no Tenjin setting. Everything except the routed search and contacts needs no Tenjin call and runs in the same session. The routed search and contacts start from the next session, when the plugin's `request` tool loads; say so once and record it: `J routed skip no Tenjin request tool until the next session`.
2. **Resume.** Ask for the resume file path. `J setup resume <path>` reads only that path. If the path is a placeholder or does not exist, it asks and reads nothing. Never search the person's files.
3. **Profile.** Build with the person and save with `J profile set '<json>'`. Code checks the shape and refuses a bad one with the reason. Shapes: `places` list of strings (not objects), `remote`/`includeOld`/`updates`/`hn` true or false, `windowDays` positive number, `sweepHour` 0 to 23, `watch` list of `{"url"}`, `search` `{"role","place","remote","roleWords"}` with `roleWords` an optional list of strings, `facts` object of text/number/true-false, `eeo`, `unattended` (lists of strings; `minPay`, `minScore` numbers). `search.role` also filters watched-board titles by its words; `search.roleWords` widens it:
   - `facts`: first_name, last_name, email, phone, linkedin, github, website, location, current_company, authorized_to_work, requires_sponsorship, salary_expectation (only what they give).
   - `places`: a city means that city. `remote: true` only if the person says remote.
   - `watch`: careers links the person pastes, `[{"url":"https://boards.greenhouse.io/acme"}]` (Greenhouse, Lever or Ashby). Code reads the board from the link. A company page with only `?gh_jid=` has no board: ask for the board link. No cap.
   - `search`: `{"role":"...","place":"...","remote":false}` for the daily routed search (references/search.md).
   - `windowDays`, `sweepHour` if they ask.
4. **EEO choice.** Voluntary demographic questions follow one explicit choice: `{"eeo":"decline_all"}` or `{"eeo":{"answers":{"<question label, lowercase>":"<answer>"}}}`. Do not choose for them.
5. **Guard hook.** Explain: one PreToolUse hook in `~/.claude/settings.json` that checks browser calls during an apply batch, runs on this computer, sends nothing, and is removed with `J guard uninstall`. Ask separately. On a yes, `J guard install`. If the write is refused, apply waits (unattended cannot run); say so.
6. **DeepSeek subagents.** `J setup deepseek` reads the state. If on, explain: a DeepSeek worker has no Claude in Chrome tools, so every application would stop, until Tenjin's DeepSeek workers can use Claude in Chrome. Only on a yes: `J setup deepseek --yes`. If they keep it on: `J setup deepseek --keep` (applications then hold as `deepseek_on`).
7. **Remote Control, once.** Say it lets the phone get the push and answer while the session, Monitor and Chrome keep running here. The person turns it on: `/remote-control`, or "Enable Remote Control for all sessions" in `/config`, plus the Claude app and its push toggles.
8. **Unattended (only if they ask).** Set `profile.unattended`: `roles` (title words), `places`, `remote`, `minPay`, `excludeCompanies`, `excludeLevels`, `minScore`, `hosts` (greenhouse, lever, ashby). Show it and ask for a clear yes. Ask separately what to do with optional writing fields: `skip` or `wait`, no default. Then `J consent record unattended --optional-writing skip|wait`. Ask separately whether unattended runs may submit new writing (text the person has not approved for that exact question). Many people say no: unattended can then still upload the resume and reuse earlier answers. Only on a clear yes, `J consent record writing`. `J consent revoke unattended|writing` undoes either. Unattended turns that the Monitor wakes can stop at a permission prompt, because the skill's `allowed-tools` grant clears at the next message; this skill writes no allow rules into settings. Open each allowed host's public board page once with the person present so Chrome allows the site for the session. Chrome stays open, the computer awake, the session open.

A daily Desktop scheduled task running `/job-search sweep only` is an option for someone who will not keep a session open. It never applies.
