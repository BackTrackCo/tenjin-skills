# Setup and the start

Setup asks only what it needs now; the rest comes when it matters. Nothing here asks about Tenjin or stops for it: `J tenjin` only sets the hint state (`missing`, `outdated`, `unfunded`, `ready`), and Tenjin comes up as a recommendation at a hint moment, after a free result (references/questions.md).

## The first run, in order

1. **The resume**, a plain question: "Share your resume: drop the file here, paste a link, or paste the text." Never ask for "the path", and never search the person's files. `J resume set --file <path>` (a path, or a file dragged into Claude Code, which arrives as a path; a PDF or Word file is read by you with your file reader, then `J resume set --text` saves its text), `J resume set --url <link>` (code fetches a public link once: that exact URL, https only, at most 3 redirects, local, private and never-automated hosts refused at each hop; a PDF is saved as `resume.pdf`, a page as `resume.txt`; a sign-in answer is reported, and a connector the person has connected may read it, otherwise ask for a public link, the file or the text) or `J resume set --text` (the text on standard input). A LinkedIn profile link is never fetched or opened by the skill: with Tenjin code reads it through the router (`linkedin_profile`); without Tenjin it is a hint moment and you ask for a PDF export (LinkedIn: More, Save to PDF) or the text. The link is read once; a new `J resume set` replaces it. A text-only resume has no file: a form that needs one holds that job (`needs_resume_file`) and asks once for the file. In a career-ops folder (`cv.md`, `config/profile.yml` and `data/pipeline.md` all there) run `J setup careerops` instead: it reads `cv.md` and `config/profile.yml`, and you ask nothing they already answer. Dedupe then also skips the URLs in `data/pipeline.md`, `data/applications.md` and `data/scan-history.tsv`. Ask once whether each job that passes review may be added under `## Pending` (references/careerops.md); on a yes `J setup careerops --pipeline yes`.
2. **Read the rest from the resume**, never as an open question: the role, the role words for the search rounds (synonyms and levels), the place (as the resume gives it, so a city stays that city) and remote (only if the resume or the person says remote). Save with `J profile set` and `search.sources` saying `resume` for each. Where the resume really leaves one open (two tracks, no recent role), ask one choice question: `J ask resume --json '{"header","question","guess","next"}'`, the guess first as "(from your resume)".
3. **One question-tool call** (mark "Three quick choices" done after `J start record`): `J ask start` prints it. Three questions: the apply mode ("Ask me each time (Recommended)", "Auto apply, approve new answers", "Fully auto apply"; attended is the default and the answer when none is given; the middle mode still drafts the answer to a new required question and only that job's submit waits), the search frequency (every day, twice a day, once a week) and the positions ("50 now, 10 daily (Recommended)", "100 now, 20 daily", "20 now, 5 daily", "No limit", or "Other": your own numbers; "No limit" and no answer record nothing, never the recommended numbers: `J start record --no-limit`). Then say the one reminder line it prints: type `/rc` to get the notifications on the phone. It is not a question and nothing is recorded. Record the answers: `J start record --mode attended|auto_no_new|auto_write --frequency daily|twice_daily|weekly --catch-up <n> --per-day <n>|none --words "<their words>"` (older form: `--positions <n>|none|skip`). The catch-up applies once, to the first period; after it the daily number applies, split across a twice-a-day period (the first takes the odd one) and counted for 7 days in a weekly one. It is a most, not a target: no weaker fit fills it. Change them later, outside a batch, with the same command or `J frequency set`.
4. **An auto mode also needs**, shown back for a clear yes: the unattended rules (`profile.unattended`: `roles`, `places`, `remote`, `minPay`, `excludeCompanies`, `excludeLevels`, `minScore`, `hosts`), then `J consent record unattended --optional-writing skip|wait` (the person picks; `J ask optional-writing`). For "Fully auto apply", `J consent record writing` too. The dry run comes before the first unattended submit.
5. **Then the free search and the report** in the same session (`J work`, references/search.md). The first report says what was searched, from where.

## Later, at their trigger

- Leaving other items: `J leave search web need:<kind> --reason no_web_search` (comes back at the next period) and `J leave contacts:<jobkey> --reason none_found`; a post batch is never left. `J retry <key>` is the person's own "try again"; `J fact set account <host>` says they have an account there (a `sign_in` job returns).

- A form fact (phone, work authorization, sponsorship, pay): the job holds as `needs_facts`; ask then (`J ask fact` for fixed answers), save with `J fact set <name> <value>`.
- The EEO choice, at the first form that has voluntary demographic questions: `J ask eeo`, then `J profile set '{"eeo":"decline_all"}'`.
- A watched company: there is no question. A board joins the list when one of its jobs passes review; the person can paste a careers link (`profile.watch`, `[{"url": "..."}]`) or remove a company (`J watch remove <name>`).

## Profile shapes

`J profile set '<json>'` checks the shape and refuses a bad one with the reason: `places` list of strings, `remote`, `includeOld`, `updates`, `hn` true or false, `frequency` daily, twice_daily or weekly, `windowDays` positive number, `sweepHour` 0 to 23, `watch` list of `{"url"}`, `search` `{"role","place","remote","roleWords","variants","sources"}` (lists of strings; `sources` says `resume` or `person` for each value), `facts` object of text, number or true/false, `eeo` `"decline_all"` or `{"answers": {...}}`, `unattended` (lists of strings; `minPay`, `minScore` numbers), `careerOps`. `search.role` also filters watched-board titles by its words; `search.roleWords` widens it.

## Other setup notes

- The watcher is `J watch`, a background command (Bash `run_in_background`) that ticks every minute, prints nothing on a quiet state and exits 0 with one line when work is due; that exit wakes the session, and the round ends by starting it again (it does not exit again for the same due set). It records its process id in the lease and refreshes a liveness field from a timer that runs through long ticks; a lease whose process is dead or whose field is older than twice the tick interval is reclaimed by the next `J arm`, and every J command reports `watcher: stopped` until it is started again. The Monitor tool is not used.
- Unattended turns that the watcher wakes can stop at a permission prompt, because the skill's `allowed-tools` grant clears at the next message; this skill writes no allow rules into settings. Open each allowed host's public board page once with the person present so Chrome allows the site for the session. Chrome stays open, the computer awake, the session open.
- A daily Desktop scheduled task running `/job-search sweep only` is an option for someone who will not keep a session open. It never applies.
- The skill never installs Tenjin unasked, and changes no Tenjin setting.
