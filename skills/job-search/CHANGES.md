# Changes

## 0.1.0

First release (v0). Watched companies from pasted careers links, read free from Greenhouse, Lever and Ashby boards; a daily routed search through Tenjin by a Haiku step, checked by `jobs.mjs ingest`; review, sheets, attended and unattended applying through Claude in Chrome behind its gates, rules and lessons, release check.

Unattended applying keeps new writing behind its own consent, separate from the unattended consent: sheet fields carry source tags, earlier answers live in `answers.json` and match by a code-only rule, and a job with new writing holds as `writing_needs_yes` until the person approves the text or records the writing consent.

Jobs found on platforms are applied to on the employer's own application page, found by apply link, board probe or the employer's careers page (`exact` or `confirmed` only), on any host except a deny list (LinkedIn, Indeed, Glassdoor, ZipRecruiter, Monster, SimplyHired, CareerBuilder, Dice, Wellfound, the Y Combinator sites, x.com and twitter.com). Those are never opened or fetched. Hacker News is read through its official API. Fill-only mode fills a form and leaves the tab open for the person to submit.

Adapted from [vraspar/find-jobs](https://github.com/vraspar/find-jobs) (MIT; its notice is in `references/careerops.md`): free web searches in every run, search rounds with new role words, HN through the HN Search API by Algolia, a "still open" check for older postings, more review warnings, contacts with sources, a report with pay and dropped jobs, career-ops folder support, and a closing line about Tenjin.

No hook and no DeepSeek question: the batch is a record in state.json, every consent change is reported and notified, and a browser result with no Chrome tools holds as `no_chrome_tools`. The free version works end to end, with Tenjin hints at the moments it would do better. Questions go through the question tool, the start asks the resume path then one call (apply mode, search frequency, positions per period, Remote Control), form facts and EEO come at their trigger, the watch list builds itself, and every contact that can be messaged gets an example intro draft.

With Tenjin, search rounds run in code through the router (`router.mjs`, one `tenjin mcp` process per round, one adapter per supplier). Hiring posts get an outcome each; a post with no job posting becomes a reach-out lead with an intro draft. Contacts ask how many jobs the first time. Loosening the positions rule or a fill-only rule needs a new unattended consent. An unattended notification carries the Tenjin hint when it fits.

The watcher wakes the model only for due work it can act on, and only when the due set gains an item or an item changes; its last wake set is kept in state, so a re-arm or a restart repeats nothing. `J leave <key...> --reason <reason>` records that the model decided to leave an item (a closed list of reasons); a left item returns only on news about it, an answer or a rule change, never on a timer. Items that wait for the person never wake the model.

Determinism audit: code does the mechanics and the model only the judgment. Re-verifying runs in the watcher and never wakes the model. A release line goes to the report and the notify set with no wake. The careers-page step is asked only for the jobs this period can use, with the router's finder first. A follow-up never wakes the model (`J ask follow_up`, `J outcome`). Routed needs run one by one in the watcher: a need with no adapter or an unknown supplier leaves one Haiku item (`need_due`) and the others still run. One wake per round, at its end: nothing is sent while code is still reading (Hacker News in chunks); a notify line rides an actionable wake, a notify-only wake comes at most once per round for a changed waiting set, and never after "Not now" to Remote Control. A sheet with no new writing goes straight to `apply_ready` (Greenhouse questions are read in code); one writer call per round covers the sheets, the lead intros and the contact intros (`J write-prompt --round`). A hiring post's board links, handle and emails are read in code; a post with a board link becomes a posting with its author as contact; a lead needs no record when code has its handle or its one email; an unreadable post is `not_hiring` with a reason and does not come back unless its text changes. `J search plan` prints the free searches' queries and code sorts the raw results. `J contacts route` runs the people search in code and drops people outside the job's city. `J leave` takes every work-list key (a search item comes back at the next period, a post batch is never left); an `other_system` job returns when a release adds the system, a `sign_in` job when the person adds an account (`J fact set account <host>`). Each wake and each subagent run is logged and the report shows the day's. The watcher command and the board list command no longer shadow each other. Outreach: an intro email to an address the poster published, word for word in the post, goes from the person's own Gmail through the Gmail connector after a batched yes (`J email batch`, `approve`, `next`, `sent`), or without a yes under a separate, revocable `email` consent; one email per address in 90 days, no follow-up, no attachment; a connector that only drafts makes Gmail drafts, and with no connector the report shows a `mailto:` link. An X DM is the person's: the report gives the profile link and the text. x.com and twitter.com are never opened, scripted or fetched. `J work` exits 0 for an empty list (the JSON says `empty`). Start and resume: the first question asks for the resume itself (a file, a link or the text) and `J resume set --file|--url|--text` saves it; a public link is fetched once in code (that URL, https, at most 3 redirects, local, private and never-automated hosts refused at each hop); a LinkedIn profile link goes to the router as `linkedin_profile` (its mapper reads the recorded response: employers with dates and no job titles, string or number start dates normalized, only schools as education, no headline or skills; the profile is thin, so the target role is confirmed with the guess marked "from your LinkedIn" and a form that needs a file or work history with titles holds only that job and asks for a file or the text), and without Tenjin it is a hint moment and an export ask. The start has four questions (apply mode as "Ask me each time", "Auto apply, approve new answers" or "Fully auto apply"; frequency; positions as a first-run catch-up then a daily number; where to apply) and one `/rc` reminder line. The middle mode still drafts new answers and only the submit waits. With Tenjin the board search is a routed need in code, run through the router's catalog search tool by its id (a free step that gives a fresh offer, then the run with the board hosts, the lite type and 10 results; one recorded mapper; results are never saved, only links confirmed on the employer's board are kept, and the board's own date decides); each offer pays once, so a fresh one is fetched before every search and a used one is never sent again; it cannot answer `native` and is never a model step, and the earlier `{query}` route and its two input mappers are gone. Attended with many sheets, the report lists them and one question approves them (`J approve --all|--no-new`). `J notify result` records each push's answer for the notify-only rule. The Tenjin ask comes first: one shared `askDue` state is checked by `J search plan`, `J resume set --url` and `J work` (the careers-page task text) before any free path, and by `J leave contacts:<key>` for contacts; `J tenjin ask-done yes` holds the moment as `tenjin_setup` until Tenjin is ready. A resume link's host is resolved before every hop (and a name that resolves to a loopback, private, link-local, unique-local or unspecified address, IPv4-mapped IPv6 included, or fails to resolve, is refused); `fetch` resolves the name again when it connects, so DNS rebinding between the check and the connect is a known gap in v0. An address published word for word in an X post counts like one in an HN comment: with a handle and an address the lead's channel is email, the report still shows the DM link, and the same checks apply (batch yes or the email consent, 90 days, no attachment). The watcher is a background command, `J watch`, started with the Bash tool's `run_in_background` and started again after each round: it ticks as before, exits 0 with one line only when an actionable wake is due (the fingerprint, one wake per round, the notify-only rule), never exits because of time, and a restarted one does not exit again for the same due set. The Monitor tool is not used and `allowed-tools` drops it. The lease belongs to the session: the watcher records its process id and refreshes one liveness field from a timer that keeps running through a long tick, so a slow round never looks stopped and is never started twice (only the watcher writes the field, no J command does), a second watcher exits at once ("another session holds the lease; work attended"), a lease with a dead process or a liveness field older than twice the tick interval (a reused pid included) is reclaimed by `J arm`, and every J command reports `watcher: stopped` until the watcher is started again. The first-run start shows that it waits: a setup list only through a task list tool (`allowed-tools` lists them), never written as text, and `J start status` giving one short first message with no separate waiting line. The positions question has four options with both numbers varying ("50 now, 10 daily", "100 now, 20 daily", "20 now, 5 daily", "No limit"); "No limit" records no `period_max`. Work already in flight no longer wakes the model: `J work --commit` claims the items it prints, the watcher's wake set leaves claimed items out, a claim ends on ingest, on `J leave`, when the item is no longer due, or after 20 minutes (a little longer than the slowest claimed step, one browser application; an apply loop refreshes its claims), and an item still open when its claim times out wakes the model once. `J watch` refuses with one line naming unclaimed due work, so it starts only as the last step of a turn. Every ingest file, model-written ones included, uses the one status word `fulfilled`, and the refusal names it. Prepare without asking: in every mode a job the skill plans to apply to (an exact or confirmed posting, above the score floor, within the period's most) is prepared with no question and no shortlist step; attended, the first question about a job is its approval with the prepared application shown, and a missing fact (US citizenship, a clearance) is asked in that same call with its fixed answers and "Skip this job" (`J ask approval`, `J approve <key> --facts`); in an auto mode the job holds as `needs_facts`. The fill and the submit are one browser pass after the yes. The default report is short (a count line that names up to three of the best apply-yourself companies, the planned jobs, what needs the person now, and a last line for `J report --all`); the contacts offer is a question with 5 first and only when jobs are planned; the rules line and the wake line read in words. The skill starts no `claude` process: the orchestrator and the background watcher stay, and model steps are Agent subagents started from a turn already in progress.

Apply anywhere except a deny list: the skill prepares and applies on any employer application page, and the deny list in `graph.json` is the only host gate. A form that needs an account or a sign-in is `sign_in` (the skill never makes an account), a CAPTCHA or bot check stops as before, and Greenhouse, Lever and Ashby keep only their code adapters (API questions, board probes, open checks). On any other system the browser's first pass reads the live form to build the sheet. The open check goes through the employer's own careers page: a page on the employer's own domain that lists the job with its application page on another system is `confirmed` when the title and place match (the Haiku step returns `listings`), the page is read again once the last check is a day old, and a page that lists jobs and no longer lists the job closes it. `other_system` now means a deny-listed host only. Unattended rules may name any hiring system, or `*`. The first application on a new host shows once in `J report --all`.

Noise fixes from the live run: a left job's inputs hash is per reason (for `low_score` the role, place, level rules, resume and score floor, never a saved form fact or answer); a push goes only for items the person was not shown, marked shown by `J report`, `J ask approval` or `J shown` and shown again when the item's version changes; rule questions are question-tool calls recorded with `J rules add --from-choice "<option label>"`, the label being the person's words.

Where the person prefers to apply: a fourth start question ("Employer's site (Recommended)", "LinkedIn, I apply", "Ask me each job"), stored as `apply.where` with source `person`. LinkedIn stays denied: the skill never opens, fetches or fills it, and only shows the job's own LinkedIn link (from the postings source's apply options or the employer's posting) with the prepared answers (`J linkedin show`). A job with no LinkedIn link takes the employer site. "Ask me each job" puts the choice in the approval call (`J approve <key> --via employer|linkedin`). "Did you apply?" is a question-tool call, and a job becomes applied, with `source: person`, only on the person's word (`J linkedin applied`). A LinkedIn job counts toward `period_max` when its link and answers are brought.

Without Tenjin the free web search stays a Haiku step (`web_search_due`); with Tenjin there is no `web_search_due`.

The once-per-session Tenjin ask lists everything (`tenjinOffer`): the moment's gain first, then every other line named by what it does, then the cost line (pay per use from a funded wallet, an estimated few cents a day at the default pace). Every routed need has a line (a test checks it); a hint stays one line about its moment; there is no writing line yet.

Choices only when the options hold the answer: a place, a role with no clear guess, a phone, pay, an address or a name is a plain question with the guess in its text; a form fact uses the form's own options word for word (at most 3 plus "Skip this job") or a plain list; EEO is asked per field with the form's own options and reused only for the same option text; the follow-up has no "through Other" option; the positions text drops the free-text mention; email over 16 drafts offers "Pick in groups of 16"; `validateAsk` refuses any text that names the free-text option; the leftover resume path question is gone.

Answers from the skill's own records: "where did you hear about this role" is answered by code from the source the search recorded, mapped to the form's own option with a fixed word list per source (tag `record`, no writing consent), with a saved answer winning, a short phrase for a free-text field, and no match holding as a normal new question.

Apply modes and approvals: "Fill it, I submit" is in every approval (`J approve <key> --fill-only`) and in the list question (groups of 12); the start question has four modes ("Ask me each time", "Auto apply" with the two auto modes in a follow-up, "Fill only, I submit", "Just open the pages"); `J open` opens a page in the person's own browser, also as the fallback for a job the skill must not or cannot fill; approvals come only from `J ask approval|approve`, a fact never shares a call with its approval, `J ask acknowledge` handles a form's legal terms, `J may-submit` runs right before every submit click, `J approve --withdraw` takes a yes back, and one state line follows every approval.

Claude in Chrome and Remote Control: `J chrome set on|off` is recorded at every start (on clears the Chrome holds and `noChromeTools`), options that need Chrome carry a note when it is off, and the reminder is built by `rcReminder()` from `J rc set on|unknown` and whether a push was ever sent (both sentences, only the `/config` sentence, or none); `J notify result not_sent --reason off|present|none` says its sentence once.

The reminder reads the two push settings (`pushSettings()`, read-only, only those two keys, from Claude Code's global config file and then its user settings file) and names only the ones that are off or unknown; with both on and Remote Control on there is no reminder, and a sent push counts as "Push when Claude decides" on whatever the file says.

The uploads folder: files a form takes (the resume copy, a link's PDF) live in `~/.tenjin-skills/job-search/uploads/` (0700), apart from the state files, because a Chrome upload counts as a read and the state folder is outside the session's folders. `J resume set` prints a plain `say` line for `/add-dir` unless `permissions.additionalDirectories` (read-only, only that key, from the user, project and project-local settings) or `J uploads set granted` already covers the folder; the first J command on an older install copies its saved resume file into the folder; a refused upload is `J stop --kind upload_blocked` (a one-line step attended, one notification and no question unattended). No code writes Claude Code's settings.

Running in parallel: every independent subagent of a wake starts in one message as parallel Agent calls (browser ones each in its own tab; the round's one writer call stays single). `J apply next --all` hands out every job that passes the checks, one per host, and the rest wait for their host (`host_busy`, never parked); each job keeps its own claim, its own `J may-submit` check and its own stops, a stop on one job leaves the others handed out, and a closed round makes `J may-submit` say no for every open job. An unattended round no longer closes while a handed-out job is still running. The routed needs of a search round stay in turn on their one `tenjin mcp` connection, and so do the board API reads.

The person may be on the phone: in every mode that fills, a required field is never left for the browser. `J sheet check --live` adds every required live field the sheet lacks and holds the job as `needs_facts` with no fill (asked in the session with a plain question or the form's own options; in a woken turn one notification and no question). A legal acknowledgment, and in fill-only the attestation, are asked before the fill (`J ask acknowledge`, `J agree <key> <label>`) and the fill ticks them. `J sheet readback` compares the form's values, refills a field once, then holds the job as `fill_problem` with the field and its value. A filled job offers "Submit it now" (built by `J ask approval`, recorded with `J approve --submit-now`, checked by `J may-submit` on the unchanged sheet hash), "I'll submit in Chrome" and "Not this one"; the fill-only mode never reaches a submit without that answer.

A missing employer website never stops the people search and no skip is silent: code finds the website first (a link field, the posting's field, a board page's homepage, with Tenjin a company lookup by name or link whose domain is checked against the company and board names before it is saved with its source), runs the search by name and city when it cannot, marks such results weak, and never records a person from another company. `J contacts route` reports every job it did not search with its reason, and the report says "not searched: <reason>", with "returned nothing" only after a search ran. The contacts question and the Tenjin ask cover the company lookup.

The company lookup and the people search by name now follow their recorded answers: the lookup's domain is trusted only when the company's name or legal name matches, a lead's company website is compared by host, a lead can match through the company's LinkedIn page, a lead with a sales or solutions title or an out-of-date headline is weak, and the leads dropped for their place are counted in the job's report line.

Tenjin prices: `graph.json` holds one estimate per need (the recorded provider price plus the 15% routing fee, rounded up to a tenth of a cent) with the date it was checked. Every hint line names its price, and the ask lists each capability with its own price, then the pace line for the person's frequency (about 3¢ a day at one round a day, 6¢ at two, 3¢ a week at one a week). The options read "Set up Tenjin (Recommended)" and "Not now". A test ties each estimate to its recorded fixture cost. Whether a call by catalog tool id carries the routing fee is not confirmed, so every estimate includes it.
