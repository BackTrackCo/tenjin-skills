# Changes

## 0.1.0

First release (v0). Watched companies from pasted careers links, read free from Greenhouse, Lever and Ashby boards; a daily routed search through Tenjin by a Haiku step, checked by `jobs.mjs ingest`; review, sheets, attended and unattended applying through Claude in Chrome behind its gates, rules and lessons, release check.

Unattended applying keeps new writing behind its own consent, separate from the unattended consent: sheet fields carry source tags, earlier answers live in `answers.json` and match by a code-only rule, and a job with new writing holds as `writing_needs_yes` until the person approves the text or records the writing consent.

Jobs found on platforms are applied to on the employer's own posting, found by apply link, board probe or the careers page (`exact` or `confirmed` only). Platforms and Y Combinator sites are never opened or fetched. Hacker News is read through its official API. Fill-only mode fills a form and leaves the tab open for the person to submit.

Adapted from [vraspar/find-jobs](https://github.com/vraspar/find-jobs) (MIT; its notice is in `references/careerops.md`): free web searches in every run, search rounds with new role words, HN through the HN Search API by Algolia, a "still open" check for older postings, more review warnings, contacts with sources, a report with pay and dropped jobs, career-ops folder support, and a closing line about Tenjin.

No hook and no DeepSeek question: the batch is a record in state.json, every consent change is reported and notified, and a browser result with no Chrome tools holds as `no_chrome_tools`. The free version works end to end, with Tenjin hints at the moments it would do better. Questions go through the question tool, the start asks the resume path then one call (apply mode, search frequency, positions per period, Remote Control), form facts and EEO come at their trigger, the watch list builds itself, and every contact that can be messaged gets an example intro draft.

With Tenjin, search rounds run in code through the router (`router.mjs`, one `tenjin mcp` process per round, one adapter per supplier). Hiring posts get an outcome each; a post with no job posting becomes a reach-out lead with an intro draft. Contacts ask how many jobs the first time. Loosening the positions rule or a fill-only rule needs a new unattended consent. An unattended notification carries the Tenjin hint when it fits.

The watcher wakes the model only for due work it can act on, and only when the due set gains an item or an item changes; its last wake set is kept in state, so a re-arm or a restart repeats nothing. `J leave <key...> --reason <reason>` records that the model decided to leave an item (a closed list of reasons); a left item returns only on news about it, an answer or a rule change, never on a timer. Items that wait for the person never wake the model.

Determinism audit: code does the mechanics and the model only the judgment. Re-verifying runs in the watcher and never wakes the model. A release line goes to the report and the notify set with no wake. The careers-page step is asked only for the jobs this period can use, with the router's finder first. A follow-up never wakes the model (`J ask follow_up`, `J outcome`). Routed needs run one by one in the watcher: a need with no adapter or an unknown supplier leaves one Haiku item (`need_due`) and the others still run. One wake per round, at its end: nothing is sent while code is still reading (Hacker News in chunks); a notify line rides an actionable wake, a notify-only wake comes at most once per round for a changed waiting set, and never after "Not now" to Remote Control. A sheet with no new writing goes straight to `apply_ready` (Greenhouse questions are read in code); one writer call per round covers the sheets, the lead intros and the contact intros (`J write-prompt --round`). A hiring post's board links, handle and emails are read in code; a post with a board link becomes a posting with its author as contact; a lead needs no record when code has its handle or its one email; an unreadable post is `not_hiring` with a reason and does not come back unless its text changes. `J search plan` prints the free searches' queries and code sorts the raw results. `J contacts route` runs the people search in code and drops people outside the job's city. `J leave` takes every work-list key (a search item comes back at the next period, a post batch is never left); an `other_system` job returns when a release adds the system, a `sign_in` job when the person adds an account (`J fact set account <host>`). Each wake and each subagent run is logged and the report shows the day's. The watcher command and the board list command no longer shadow each other. Outreach: an intro email to an address the poster published, word for word in the post, goes from the person's own Gmail through the Gmail connector after a batched yes (`J email batch`, `approve`, `next`, `sent`), or without a yes under a separate, revocable `email` consent; one email per address in 90 days, no follow-up, no attachment; a connector that only drafts makes Gmail drafts, and with no connector the report shows a `mailto:` link. An X DM is the person's: the report gives the profile link and the text. x.com and twitter.com are never opened, scripted or fetched. `J work` exits 0 for an empty list (the JSON says `empty`). Start and resume: the first question asks for the resume itself (a file, a link or the text) and `J resume set --file|--url|--text` saves it; a public link is fetched once in code (that URL, https, at most 3 redirects, local, private and never-automated hosts refused at each hop); a LinkedIn profile link goes to the router as `linkedin_profile` (its mapper reads the recorded response: employers with dates and no job titles, string or number start dates normalized, only schools as education, no headline or skills; the profile is thin, so the target role is confirmed with the guess marked "from your LinkedIn" and a form that needs a file or work history with titles holds only that job and asks for a file or the text), and without Tenjin it is a hint moment and an export ask. The start has three questions (apply mode as "Ask me each time", "Auto apply, approve new answers" or "Fully auto apply"; frequency; positions as a first-run catch-up then a daily number) and one `/rc` reminder line. The middle mode still drafts new answers and only the submit waits. With Tenjin the web search is a routed need in code (one small input mapper per known supplier, the recorded one a POST with `include_domains` of at most 5, `max_results` of at most 10 and `date_from`, the other unrecorded; one adapter for any list of title, URL and snippet; a result's free-text published date is read against the retrieval time or dropped; the need keeps the `site:` form; results are never saved), and a `native` answer or a missing mapper holds it for the round. Attended with many sheets, the report lists them and one question approves them (`J approve --all|--no-new`). `J notify result` records each push's answer for the notify-only rule. The Tenjin ask comes first: one shared `askDue` state is checked by `J search plan`, `J resume set --url` and `J work` (the careers-page task text) before any free path, and by `J leave contacts:<key>` for contacts; `J tenjin ask-done yes` holds the moment as `tenjin_setup` until Tenjin is ready. A resume link's host is resolved before every hop (and a name that resolves to a loopback, private, link-local, unique-local or unspecified address, IPv4-mapped IPv6 included, or fails to resolve, is refused); `fetch` resolves the name again when it connects, so DNS rebinding between the check and the connect is a known gap in v0. An address published word for word in an X post counts like one in an HN comment: with a handle and an address the lead's channel is email, the report still shows the DM link, and the same checks apply (batch yes or the email consent, 90 days, no attachment). The watcher is a background command, `J watch`, started with the Bash tool's `run_in_background` and started again after each round: it ticks as before, exits 0 with one line only when an actionable wake is due (the fingerprint, one wake per round, the notify-only rule), never exits because of time, and a restarted one does not exit again for the same due set. The Monitor tool is not used and `allowed-tools` drops it. The lease belongs to the session: the watcher records its process id and refreshes one liveness field from a timer that keeps running through a long tick, so a slow round never looks stopped and is never started twice (only the watcher writes the field, no J command does), a second watcher exits at once ("another session holds the lease; work attended"), a lease with a dead process or a liveness field older than twice the tick interval (a reused pid included) is reclaimed by `J arm`, and every J command reports `watcher: stopped` until the watcher is started again. The first-run start shows that it waits: a three-item setup list (the session's `TaskCreate` and `TaskUpdate`, or `TodoWrite`; `allowed-tools` lists them) with the resume item in progress, the turn ending on one plain waiting line, and `J start status` saying so; later waits get no list. The positions question has four options with both numbers varying ("50 now, 10 daily", "100 now, 20 daily", "20 now, 5 daily", "No limit"); "No limit" records no `period_max`. The skill starts no `claude` process: the orchestrator and the background watcher stay, and model steps are Agent subagents started from a turn already in progress.
