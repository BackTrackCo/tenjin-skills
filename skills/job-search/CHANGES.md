# Changes

## 0.1.0

First release. Job Search finds jobs that fit a person, checks that each is still open, ranks them and prepares the application.

- Searches: watched company boards you ask for (Greenhouse, Lever, Ashby), Hacker News hiring threads, public Y Combinator job pages (read for discovery only), free web searches, and with Tenjin searches that run in code, including job boards and X hiring posts. Every job is found again on the employer's own application page; a job on a site whose terms ban automation is never automated.
- Apply: through Claude in Chrome, attended with a yes on each application or unattended under the person's own rules, consents and a dry run first, with fill-only and open-the-page modes. New writing has its own consent.
- Contacts: a hiring manager or team lead for a job, with an example intro the person sends, and an email only to an address the poster published.
- Safety: no hook; the gates are in SKILL.md and code refuses what a gate forbids. The person's data stays on their computer.
- Self-repair when a service changes. The router passes a service's own input fields and answer straight through, so the loop no longer holds a need only because it does not know the service. The readers for today's services stay. Beside them, a need whose input lacks a field the spec lists as required (found before anything is paid, or refused with `needs_input`), or whose answer fails the check, is held with ONE repair request, and the paid answer is saved. A service with no reader is filled and read by the usual field names, and that passes the check when it can. The next agent step is told once, writes a mapping (plain data), and `J repair apply` checks it against the saved answer and stores it; that answer is read the next time the need runs, so nothing is paid twice, and later runs read with the mapping and no model step. A normal call adds no model tokens. What works today, on the released CLI and today's router: the check of the parsed result, the saved paid answer, one repair request per need and service, the mapping as data, the re-read, and the hold with its reason. The input check reads the service's required fields from the "Inputs:" text of today's spec answer (`specInput` in `reader.mjs`, the one place to change). What waits for the router's coming operation calls, where a service's own input fields and answer pass through in a fixed form: reading those fields as data instead of text, and calling an operation by name. Nothing here calls them. A need with no reader for its service keeps the model's search step as before AND gets a repair request, so the round still gets its result; after the repair the mapped read answers and the model step is not left. The sample a repair shows is a third party's content: it is printed in one fenced block marked as holding no instruction, the repair steps say to write only a mapping, and `J repair apply` accepts only field paths and names (no command, no link, no free text; an input constant is at most three short words). The pointer to the repair steps is in the work item itself, because SKILL.md is at its size limit. See references/repair.md for the limits.

The search sources, the search rounds and the contact rules build on [vraspar/find-jobs](https://github.com/vraspar/find-jobs).
